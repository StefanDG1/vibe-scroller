# Prepare a personal deployment

Mode: how-to. Updated October 3, 2026. P05 implementation is authorized by the owner's post-V1 request. One user-operated path retains the selected stack. Independent acceptance needs two clean-checkout testers and a retained-data upgrade. Fully self-contained hosting and all-local computation remain unsupported claims.

| Use                         | Your own requirements                                                  | Limits                                                               |
| --------------------------- | ---------------------------------------------------------------------- | -------------------------------------------------------------------- |
| Labeled demo                | Node 24, pnpm 12.3.4                                                   | No accounts, payment or compulsory telemetry                         |
| Metadata library/export     | Convex, WorkOS Google/email codes; local Next.js or Vercel             | No live Stripe or analytics required                                 |
| Upload/private frames       | EU-jurisdiction private R2, encryption and scoped grants               | Storage costs and retention apply                                    |
| Personal analysis           | Paired device, supported local ASR, eligible personal ChatGPT account  | Remote inference is not all-local; no pooling                        |
| Selected-project review     | Own GitHub App/installation, verified reasoning route                  | Read access does not authorize coding                                |
| Optional cloud coding/media | Own eligible Vercel Sandbox, verified images, trusted brokers and caps | Persistence disabled; no Netlify/E2B fallback or broad worker tokens |
| Optional billing            | Own development sandbox; separately approved live operator setup       | Never inherit founder merchant accounts or catalogue IDs             |

Follow [local development](local-development.md). One `pnpm install --frozen-lockfile` installs application packages. `node scripts/setup-preflight.mjs --demo` checks demo configuration; `node scripts/setup-preflight.mjs` checks account settings without printing values. `pnpm setup:local` prepares the ignored frontend environment. No helper calls providers or grants authority.

Use [provider setup](PROVIDER-SETUP.md), [authentication](operations/authentication.md), [personal runner](operations/personal-analysis-runner.md) and [Vercel Sandbox](operations/vercel-sandbox.md) for real capabilities. Workspace quotas and reservations remain intact. Missing processing configuration yields unavailable routes, not free work. OS/funding support comes from tests. Windows local coding remains disabled after its isolation failure.

Use your own Vercel project with root `apps/starter`, Node 24, fixed Basic builds and queued concurrency. Production secrets stay out of previews; backend variables are separate. Supply your own callback/domain/session secret and legal identity. Operator deployment names, broker origins, credentials and company identity are not sample values. Inspect costs/terms before creating billable resources.

Use [the study protocol](operations/independent-use-study.md). Two testers with clean checkouts and their own accounts import a permitted source, obtain cited analysis, export and explain coding options without private founder help. Record effort, assistance, approval waits, billed resources, OS, commit and failures separately. One tester upgrades to a verified immutable version and confirms retained data. Setup-time targets follow observations.

Before upgrade export data, retain independent deletion markers and preserve provider configuration privately. Check schema compatibility in a separate environment. Frontend rollback does not reverse database writes, reservations or external PRs. Voluntary opaque study IDs suffice; no compulsory telemetry or production data copy is needed.
