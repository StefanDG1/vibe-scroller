## Enforcement and bounds

Existing sources, categories, repository snapshots, profiles, budgets, inference adapters, execution and draft PRs remain the foundation. New records use the same Convex workspace ownership. No cross-workspace cache, embedding provider, training, V2, pooled subscription inference or paid fallback was added.

Backfill classifies existing analyzed insights in pages of ten sources. It does not process media or charge for old analysis. Every eligible analyzed insight is available through topic membership pagination. A source retains up to twenty insights and eight topic names per insight, within existing analysis contracts. Topic membership is many-to-many. Source references bind the source ID, generation, current revision timestamp and stable insight ID. Manual names, pins, exclusions, moves, merges and splits persist independently of automatic classifications. A merged topic redirects later classifications. Topic changes increase their version.

Funded explanations require a workspace owner/admin's reviewed policy. The form defaults to automatic organization with a proposed 50-credit monthly ceiling; the server accepts 10–200 credits. Configuring this ceiling does not add credits or raise provider/service ceilings. Each evidence batch reserves ten credits and includes at most twelve insights. Topic explanations and evaluations use the existing inference route, a maximum 2,400 output tokens and the adapter's bounded provider requests. A job's five-minute dispatch deadline is conservative relative to those provider timeouts. There is one claim per job and no automatic inference retry. Interrupted provider work becomes unknown and retains its cost hold. Queued work can resume through the recovery sweep. Pausing a policy or a kill switch prevents new dispatch and stale commits; existing knowledge remains readable. The monthly policy counter conservatively accounts for approved batch ceilings.

Topic and idea lists paginate thirty records. Indexed workspace source-title search, topic-title search, readiness, recent-update and current project-applicability filters preserve pagination. Source and insight totals cover all included memberships; overview summary counts cover the latest twenty batches. Each topic-detail page pairs twelve memberships with the explanation for that evidence batch. Coverage explicitly excludes other batches, unprocessed/deleted evidence and omitted repository files. A project's ideas filter does not imply the whole library fit in one prompt. Users browse the full paginated corpus and choose one or several repositories for a bounded evidence batch; each repository gets a distinct evaluation, budget reservation and optional issue. No-fit, already-implemented, unsupported, needs-context and deferred states remain valid.

The repository checklist displays thirty filtered choices at a time and supports multiple installations, search and visible-page bulk selection. Metadata discovery covers up to ten GitHub pages per installation and up to ten installation pages, refusing larger discovery rather than claiming completeness. An All repositories grant does not select code. Server selection validates every identity and the existing three/15 repository entitlement before snapshots. A selection version fences late snapshot writes. Current linked-user and installation access and the exact base are checked before evaluation and publication. Confirmed profiles survive. Unconfirmed selected projects default to quoted AI drafting, with a batch ceiling of ten credits per project. Partial failures are shown; completed profile drafts are reused and unknown profile usage blocks duplicate charges. Structured context and existing free-text profiles both support manual correction and one-action confirmation.

Issue drafts contain concise paraphrases, authenticated evidence links, inspected path/line citations, problem, fit, approach, acceptance, tests, risks, alternatives and questions. There is no coding-plan file requirement for a manual or research issue. Drafts support exact Markdown editing, preview, copy and download without issue permissions. Code/media inclusion is a separate rights choice. Credentials and signed storage/private asset URLs remain forbidden. Publication requires exact draft version/hash, repository, verified visibility, current Issues write permission, allowed workspace role and explicit publication-rights approval. Narrow installation credentials are confined to the trusted publisher. No issue-only operation produces a branch, coding run, PR, merge or deployment.

An approval creates a durable attempt and the reviewed body contains a unique recovery marker. A claimed attempt cannot be claimed twice. An uncertain POST result is unknown and cannot be blindly retried. Reconciliation searches authoritative pages for the marker, up to 1,000 issues; absence does not authorize a retry. Known issue numbers refresh directly. Reads can use Issues read after a write-permission downgrade. Signed, deduplicated issue webhooks and periodic reconciliation refresh open/closed/reopened and external-edited states without modifying GitHub text. Access loss and unavailable issues are separate from closure. Closing is not implementation or benefit.

Deleted source evidence is fenced immediately in reads/exports. Paginated cleanup removes private derived output and draft text, while minimal external issue receipts survive source deletion. Workspace deletion purges new content and receipts under the existing retention policy. App deletion does not delete an external GitHub issue. Recovery quarantine pauses policy authority, jobs and publication attempts without clearing outstanding cost holds. DISABLE_KNOWLEDGE and DISABLE_ISSUES are independent worker/publication kill switches; RESTORE_LOCK remains mandatory. No hosting-machine or build-concurrency policy changes.
