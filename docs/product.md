# Product brief

CompanyNerve is a free starting point for a SaaS product. It should let a founder launch a product with accounts, organizations, billing, a coherent design, and documentation that explains how the pieces work.

The primary user is an independent founder or a small team using coding agents alongside ordinary development tools. Their customer still expects clear onboarding, reliable access, working subscription flows, and a product with its own identity.

## First usable template

The approved implementation should deliver a minimal example product with one organization-owned resource, such as a project. It includes account creation and sign-in, organization creation and switching, invitation and membership management, owner/admin/member permissions, an account page, and a Stripe sandbox subscription flow. The sample resource exists to demonstrate how to add real product logic. It is not LaunchProof or another future product.

Company configuration holds the product name/description, fixed roles, plan limits, and chosen design recipe. Other authorization rules live in backend functions. Secrets never belong in these files. Important permissions still run on the backend; configuration is not proof of enforcement.

Five design recipes cover marketing and common application states. Each recipe defines layout, density, type, color roles, forms, tables, navigation, empty states, and motion. A new product chooses a recipe and customizes its identity without taking CompanyNerve's marketing page or logo.

## The website

CompanyNerve's website explains what the template includes, shows the five design options, explains the setup process and provider dependencies, and points to documentation. Before the template is ready, its primary action is to explore the preview. When a public licensed release exists, the primary action becomes getting the free template.

The first version does not sell a template license. Paid services are a later product decision. Never advertise live monitoring, automatic security verification, autonomous agents, or paid modules as included capabilities until those products are released and integrated.

## Deliberate limits

The initial template has no generalized module runtime, arbitrary code executor, connector vault, multi-agent control plane, hosted browser workers, or ten-product dashboard. It does not clone Kinetexa's fitness features or Vydero's media pipeline. Provider credentials belong to each founder's deployments.

Success means a founder can create a new product from a tagged template release, change its brand, provision isolated development services, complete the example journey, and understand how to add their first domain feature.
