# Rehearse serving recovery in a separate environment

Mode: how-to. P03 requires a new destination; the deleted rare-echidna-358 preview is historical. No production DNS or live routing change is authorized.

1. Verify independent encrypted database/component and retained-object backups, exact commits, expiry, compatible schema and newest deletion manifest. If a suitable archive has expired or required objects are absent, capture an explicit unavailable state or obtain a fresh bounded read-only backup. Never extend archive expiry to force recovery.
2. Create one fresh named preview in the dedicated VibeScroller project, with expiring/revocable deployment credentials. Deploy tested compatible code into the empty destination. Before any import set `RESTORE_LOCK=true`, all capture/inference/local/cloud/publication kill switches, disabled live checkout, disabled real email and disabled image renewal. Verify destination identity against production.
3. Keep production runtime secrets absent. Import selected application and component tables through the official CLI. Count both scopes explicitly; assertions for application tables do not imply component verification. Apply the latest independent deletion markers before serving access.
4. Page credential/device/GitHub/repository/run quarantine until complete. Preserve PR receipts and unknown cost holds; invalidate stale execution authority and provider cursors. Pending customer work must not resume merely because it was restored.
5. Use isolated private storage with constrained writes and no production object credentials. Restore surviving retained frames with current-record checks, hashing and deletion-race cleanup using [the backup runbook](backup-recovery.md). Temporary media remains expired. Record explicit unavailable objects separately from restored objects.
6. Start the application at a separate protected test hostname with dedicated test authentication/cookie configuration. Keep dispatch disabled; introduce no production callback, webhook, payment, PR or email credentials. Permit only the authorized test identity after reconciliation; verify foreign denial and deleted-source denial through real HTTP/browser requests. An internal privileged CLI read alone does not pass serving acceptance.
7. Interrupt and resume the rehearsal; compare selected recovered data, hashes, tombstones and unresolved holds. Rehearse rollback at the test destination, preserving its chosen state. Measure elapsed restoration and actual backup/data-loss timestamps. Do not publish an RTO/RPO promise from an estimate.
8. Relock, revoke temporary sessions/deploy keys, delete the exact temporary destination through provider confirmation and remove bounded plaintext. Preserve encrypted evidence privately within its retention. Verify the serving production identity/domain still point to the prior production path.

The October 3 regression demonstrated that privacy sweep could schedule object deletion while locked. The fix pauses sweep/retention cleanup, billing/PR reconciliation, callback processing, object deletion and email dispatch under the restore lock. Unit tests verify a restored pending deletion is untouched and configured provider keys cannot trigger these dispatch paths. Explicit marker application/quarantine remain available; the lock does not pretend those are completed.

Local tests and locked-hosted import are independent evidence classes. Full serving recovery, every component/object, interruption/rollback and cleanup must each have receipts before P03 is complete.
