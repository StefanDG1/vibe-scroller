Mode: reference. Updated October 3, 2026. [Readiness](V1-READINESS.md) is the current release record; the [deployment receipt](operations/evidence/paid-release-deployment-20261003.json) identifies the demonstrated build.

| Capability                                | Evidence and limit                                                             | Next action                                                                         |
| ----------------------------------------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------- |
| Browser library, URL/upload/import        | Production owner evidence; metadata ZIP import stays local                     | Start with [the tutorial](HOSTED-TUTORIAL.md)                                       |
| Audio and selected frames                 | Actual Google and personal-route processing; sampled frames are not exhaustive | Inspect coverage, evidence and uncertainty                                          |
| Public media retrieval                    | Bounded production worker; private/deleted/blocked links can fail              | Supply media only with permission                                                   |
| Project relevance and plans               | Actual selected-repository useful/no-fit examples                              | Confirm project context; plan acceptance is separate from coding                    |

| Personal ChatGPT analysis                 | Narrow owner account-backed paired-laptop evidence                             | Own eligible account and consent; laptop awake and runner connected                 |
| Hosted commercial ChatGPT, Windows coding | Disabled pending commercial rights or isolation evidence                       | Explicit eligible metered route or plan export                                      |
| Personal deployment                       | Preparation authorized; independent setup/upgrade tests pending                | Follow [setup](PERSONAL-SETUP.md), record help and waits                            |
| Android hardware, Telegram, Gemini        | Deferred/unverified                                                            | Paste/upload fallback; widths do not prove hardware acceptance                      |

Metadata capture, completed analysis, accepted plan, draft PR, merge and measured benefit are different facts. Demo fixtures contain authored records; customer content stays private. Media/evidence follow published retention and deletion policies.

| Symptom                           | Safe response                                                              |
| --------------------------------- | -------------------------------------------------------------------------- |
| Source unavailable                | Inspect status; permitted-media fallback rather than blind retries         |
| Budget exhausted or unknown usage | Preserve reservations; stop paid work and reconcile usage                  |
| Laptop offline                    | Resume the paired runner or explicitly select an available quoted route    |
| Disconnected provider             | Reconnect the intended account/repository; refresh context before approval |
| Unknown write/checkout result     | Read authoritative state before retrying; do not duplicate side effects    |
| Failed isolated checks            | Inspect failure; refine/export or authorize bounded repair                 |
| Foreign-workspace exposure        | Report privately; current membership is required for private objects       |

Support uses the published contact route. Include version, safe error code and time; omit token-bearing URLs, source text, keys and private code. [Security reporting](SECURITY.md) and [operator controls](operations/vibescroller-deployment.md) cover escalation. No staffed 24-hour support or recovery-time guarantee is established.
