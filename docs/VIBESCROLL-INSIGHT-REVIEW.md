# Review saved insights for the VibeScroll redesign

Mode: planning review. Date October 7, 2026. Baseline `e94cb66c66f232669213a41ba67c6976100bc15d`. This changes documentation, not the application or its production data.

## Coverage and method

The completed captured library contains 108 genuine sources and 744 unique insight references. Its 1,574 topic-membership rows repeat insights across topics. Deduplication used the exact source, generation, revision and insight ID, checking that duplicate titles, claims and interpretations agreed. All 744 titles and full claims were read in source-order batches. A second pass read interpretation and verification notes for 90 selected insights, particularly uncertainty, contradictory advice and operational additions.

The ignored private review ledger gives each insight a disposition and source-specific reason. It records 289 plan inputs, 407 insights not promoted into requirements and 48 rejected tactics. A plan input may reinforce an existing choice or provide a constraint/counterexample; these are not 289 new features or independently validated findings. Not-promoted insights remain useful library material, recommendations for another project or unsupported hypotheses. Rejecting a tactic does not delete the source or change its analysis.

This review reused local completed-run artifacts and the production-verification capture from October 6. It did not query today's production corpus, fetch every original video again, run models, process media or delete records. The genuine corpus already excludes the earlier 12 test records. A genuine source titled "test" is not a fixture and stays included. No inference fee was incurred by this review. Existing model usage and subscription costs are not recalculated here.

Private audit files are `private/vibescroll-plan-review-corpus.json` and `private/vibescroll-plan-review-ledger.json`. They remain ignored and outside GitHub. This document cites selected public sources needed to explain the plan, rather than publishing the owner's complete saved history, transcripts, private project context or raw analyses.

## Tool and skill review

Keep the existing CompanyNerve shared layer and shadcn-compatible controls. Use 000h selectively. The saved mascot posts correctly identify page-mascot and IP-as-logo as candidates already documented in the plan. Original Scroll art remains required; galleries are not authorization to adopt someone else's identity.

[Drawably's current repository](https://github.com/danielwh2/drawably) provides a fixed-seed sketch option with [MIT licensing](https://github.com/danielwh2/drawably/blob/main/LICENSE). Consider a few decorative highlights or arrows in P3 only if they reinforce Scroll's style. Preserve control semantics and disable unnecessary stroke animation. Current README and old size descriptions disagree; profile the pinned implementation rather than advertising a 4 KB guarantee.

The [Rare UI saved post](https://www.instagram.com/reel/DdMRE7QspKF/) calls it open source. The registry's [current license](https://github.com/swamimalode07/rare-ui/blob/main/LICENSE) and [October 4 terms](https://www.rareui.com/terms) add Commons Clause restrictions and attribution. That is not an unrestricted MIT dependency. Exclude it from the default stack and prefer already selected alternatives. Similarly, a component catalog, AGPL tool, music list or supposedly free illustration needs exact rights and distribution review. Do not bundle DocuSeal, Recordly or a new agent framework merely because a post describes it as free.

The repository already has 12 pinned skill snapshots, including frontend-design, shadcn, unslop, technical-writing, browser-harness, SEO and architectural guidance. Available Impeccable guidance covers visual critique. Added a concrete design handoff and future optional mascot-skill gate to the plan; installed no new skills, dependencies or MCP services in this planning pass. More overlapping skills would increase context and review overhead without helping this task. Before P3, inspect and pin only the mascot guidance actually needed, retain notices and reject remote scripts or skill instructions that conflict with owner choices.

## Gaps caught in the second plan review

1. Original V1 acceptance had no explicit crosswalk into the redesign. Added W01–W07 mapping and retained interrupted recovery, restricted/multiple GitHub installations, independent judgments, physical-phone/fresh-user evidence and exact publication review as separate gates.
2. Badge, toast, loading, optimistic update, offline and completion meanings were underspecified. Added concrete state behavior and failure acceptance.
3. The free-post promise could appear to guarantee capacity despite a shared trial cap. Added funding/readiness reconciliation and unit-cost measurement, with truthful fallback.
4. Saved link, retrieved media and fully validated analysis could be confused. Added source support/coverage matrix, failure cases, safe normalization and explicit test provenance.
5. Search, graph, cache and assistant dependencies needed stronger revocation/correction detail. Added immediate denial plus bounded cleanup and late-result fencing.
6. Feedback could overlearn from clicks or dismissal. Added reasoned, reversible, project-scoped preferences and no automatic context overwrite.
7. Public discovery and future assistant intake lacked explicit indexing/network boundaries. Added private-page exclusion, permission-safe previews, redirect/private-network checks and prompt-injection enforcement outside models.
8. The four foundational briefs still led with the old name and developer-only target. F014 reconciles the current direction without rewriting historical evidence or inventing new market validation.

The final review keeps one source of truth, one chart system, one coordinated component layer and bounded views. A graph database, default embeddings, a new agent fleet, universal social sync, general calendar/health assistant and autonomous business features are unnecessary for this release. Creator recommendations for shame, fake proof, disguised urgency, copied viral media, unsolicited outreach and unverified revenue guarantees are rejected. Referral rewards, native store expansion and adaptive marketing await a demonstrated need, cost model and their own authorization.

## Verification and remaining uncertainty

Coverage and deduplication passed a local comparison of the ledger against all original membership references: 744 identities, 108 sources, complete dispositions and 90 deeper reads. `pnpm validate` passed for 196 documents and 12 skill snapshots. Prettier passed for all 11 changed/new Markdown files; `git diff --check` passed. Both private audit files are ignored. These are document and coverage checks, not new product tests, browser acceptance, deployments or integration executions.

These changes improve the implementation brief. They do not establish higher conversion, faster processing, better recommendation quality, customer demand or legal clearance. Those need the proposed observed-user tasks, comparable usage/outcome data, exact provider contracts and original V1 gates. There is no new owner question needed to finish this planning review.
