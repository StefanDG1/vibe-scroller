# Deliver scoped completion Events through verified persistent webhooks

Mode: reference. Decision October 7, 2026. Status: implemented candidate, activation and actual host acceptance pending.

The supported OpenAI Events contract uses `events/list`, `events/subscribe` and `events/unsubscribe`, finite renewable subscriptions and signed HTTPS callbacks. The pinned MCP SDK supports typed custom request handlers, so extend its validated modern transport; do not replace envelope validation or advertise its in-process bus as persistent delivery. Events remain disabled until the adapter and actual supported-host journey pass. Widgets and unsupported hosts remain outside this slice.

Persist only bounded explicitly selected source-status subscriptions and durable delivery receipts. Completion means the server recorded the selected work as ready; it is not evidence of usefulness or successful host processing. Payloads contain minimal IDs, status and a protected review URL, with no titles, transcripts, media, code, prompts or instruction-bearing text. Cursor is null and missed events are not replayed. Stable event/subscription identity, bounded retry, finite expiry and current grant/source checks prevent duplicate logical work and stale access.

Verify every new callback or replacement secret with a fresh single-use signed challenge before sending application data. Reuse the existing public-address policy, connect to the validated address with original TLS hostname, impose byte/time bounds and reject redirects. Cache successful verification for at most five minutes only for the same principal, callback and secret. Resolve at every connection, including retries. HTTP receipt is separate from actual host acceptance. Normal deliveries use the received HTTP status and close the response without retaining its body; an irrelevant oversized success body must not cause another delivery. Verification challenges still require a bounded matching body. HTTP 410/413 responses stop delivery; other retryable failures have bounded backoff.

Provider revocation must be checked during background delivery. The available official public-PKCE contract supplies bearer-authenticated userinfo, not a verified app-consent lookup endpoint. A background subscription therefore requires a purpose-bound encrypted short-lived Connect access token and callback secret, never an authorization code, refresh token, local Codex OAuth credential or plaintext bearer in function arguments. Dedicated versioned Events encryption is separate from existing private provider keys. Ciphertext binds the canonical resource and verified principal. Authority ends no later than token/grant/subscription expiry; renewal requires another valid authenticated request. Scheduled expiry removes runtime ciphertext, with bounded cron recovery for interrupted cleanup. The dedicated Events key is not an archive credential and must never be supplied to a restore. Restored ciphertext and app grants are quarantined before serving. This narrowly refines ADR 085's header-only request boundary for encrypted background authority. Actual userinfo revocation behavior is a release gate, not inferred from local tests.

Grant replacement/revocation, account/workspace/source deletion, membership loss, rights withdrawal, generation changes, restore lock, provider rejection and expiry deny future dispatch. Current app authority is checked after DNS resolution immediately before callback transmission; an already transmitted request cannot be retracted. Restored subscriptions and pending deliveries remain quarantined and cannot resume old authority. Cleanup removes expired credential ciphertext and delivery rows in bounded pages. No event permits inference, reservation, coding or publication.

Required checks include actual SDK modern-envelope/custom-method behavior, callback DNS rebinding/private-address/redirect/time/byte limits, Standard Webhooks signing verification, challenge mismatch, durable retry/deduplication/rotation/expiry/unsubscribe/revoke/deletion/restore guards and real supported-host completion after relevant UI closes. Record any skipped external gate explicitly.

Primary contracts inspected October 7: [OpenAI MCP Events](https://developers.openai.com/plugins/build/mcp-events), [Standard Webhooks signer](https://github.com/standard-webhooks/standard-webhooks/blob/main/libraries/javascript/src/index.ts), installed MCP server 2.3.1 custom-handler types and existing trusted public-preview network implementation. No new provider permission, commercial approval or successful host event is asserted.
