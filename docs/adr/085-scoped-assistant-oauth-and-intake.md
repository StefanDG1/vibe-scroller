# Separate assistant OAuth from app authority

Mode: reference. Decision October 7, 2026. Status: implementation candidate; production assistant access remains disabled.

Use the existing WorkOS environment's documented Connect authorization server, exact MCP resource audience and registered user OAuth clients. Ordinary AuthKit sessions and Connect identities have different issuers and authority. A Connect identity cannot bootstrap an app account or call ordinary app queries and mutations. No machine-to-machine identity supplies a user's knowledge access.

Each tool checks the registered client, OAuth scope, active app user, current workspace membership and the user's separately reviewed app grant. Grant creation requires app authentication within 300 seconds, exact source generations/revisions, compare-and-swap versioning and an expiry of at most 30 days. The interface defaults to seven days. Revocation needs no additional authentication ceremony. Confirmed stated context has its own exact version and scope; changing the context withholds the former grant's answers.

The Next endpoint verifies the official issuer, RS256 signature, audience, expiry, client, user subject and consent identifier. It forwards the bearer only in the authorization header to a dedicated Convex HTTP action. That action calls the official bearer-authenticated userinfo endpoint on each tool call, requires its subject to match the verified identity and rechecks current app authority in the subsequent internal transaction. Tokens never become database function arguments, stored app credentials, model inputs or logs. WorkOS public PKCE applications cannot create client secrets. The adapter requires no client secret and forwards tokens only to the exact validated issuer's official userinfo endpoint; response identity fields beyond the subject are discarded. No administrator token bridge is used.

Search reads at most five selected source records per page and returns at most 20 clipped matching ideas. Fetch returns a selected current idea or at most 20 ideas with protected app citations and up to ten timestamp references each. It exposes no transcripts, original media, signed asset URLs, credentials or prior conversations. Correction, rights changes, deletion, membership loss, grant expiry and revocation fence future retrieval. Already disclosed conversation content cannot be retracted by the app.

Explicit link intake reuses the capture implementation after current server authorization, retaining URL restrictions, rights, quotas, canonical deduplication and audit. Client request keys are namespaced and hashed with the canonical URL. Assistant intake suppresses link previews and starts no external download, model work or budget reservation. Approved private intake filing does not replace existing filing. A separate receipt binds status access to the exact actor, client and grant version. Saving does not automatically grant retrieval of the new post. Analysis requests return the existing app review flow for the actual provider, funding route and cap.

Pin `@modelcontextprotocol/server` 2.3.1 and preserve its complete mixed license notice. Its protocol revision and SDK major version do not broaden product V1. Actual modern 2026-07-28 envelopes and stateless legacy transport, scope challenges, bounded bodies and RSA signature/claim rejection have local tests. Persistent Events, widgets, real client consent, account disconnection and production citation acceptance need their own evidence. An in-process subscription bus is insufficient evidence of persistent signed host webhook delivery.

The dedicated WorkOS environment now has five custom knowledge/intake permissions, the exact canonical resource indicator and one manually registered third-party public PKCE ChatGPT client. Its callback was copied from the actual host dialog. The first create request used the wrong SDK redirect-object shape and failed with 422; the corrected request succeeded. Client-secret creation then failed with the provider�s public-PKCE restriction before any secret was created. Dynamic registration and client metadata registration are not enabled. Their documented default OIDC scopes do not establish custom knowledge authority. The runtime remains disabled pending real linking, selected-evidence retrieval and provider revocation acceptance. Preserve third-party consent; do not label an external assistant first-party to suppress it. Verify any required organization ownership and resource configuration before activation.

Affected checks include ordinary-account isolation, current source/context versions, OAuth client/scope/subject/consent rejection, provider and concurrent app revocation, bounded request bodies, idempotent intake, source/network restrictions, funding boundaries, export and bounded account/workspace/source cleanup. Full builds, native interface review, real OAuth and exact deployment are separate from those local tests.
