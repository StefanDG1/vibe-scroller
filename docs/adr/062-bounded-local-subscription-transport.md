# Correct bounded local subscription transport

Mode: reference. Decision October 6, 2026. Status: implemented locally; publication evidence is recorded separately.

The owner authorized fixing their own subscription route and accepted local preparation plus their own Codex session. ADR 059's personal comparison boundaries and ADR 061's separate native cloud enforcement gate still apply. This change does not authorize pooled subscription access, private endpoint integration, paid API fallback, extra usage purchases or automatic issue publication.

The official Codex 0.160.0 client rejects configuration that overrides its built-in openai provider. Remove those incompatible retry overrides. Retain disabled unbounded connection retries, a single application attempt per trial source and the 180-second turn deadline. Official-client bounded default transport retries remain possible; a stopped or malformed turn does not prove that no subscription allowance was consumed. [Official configuration reference](https://learn.chatgpt.com/docs/config-file/config-advanced).

The HTTPS broker previously timed out each read direction independently. A model can legitimately send no response while computing, and an upload or stream can remain active in only one direction. A synthetic delayed-response reproduction established premature closure with that implementation. Track activity across both directions and preserve an absolute connection deadline. The trusted subscription launcher alone selects a 300-second connection cap and 180-second shared idle cap. Ordinary media acquisition retains its 90-second connection cap and 15-second shared idle cap. Destination/public-DNS restrictions, IP pinning, port 443, four active connections, 64 total connections, 300 MB transfer and five-second drain limits remain enforced.

Use the official app-server structured output format with explicit types and required properties, derived from the existing insight contract. Bind source ID, processing run ID and supplied coverage in the provider schema. Validate the returned contract and exact evidence independently before import. Fail active turns immediately when the official client exits; deliver protocol lines up to 16 MB and close on larger responses rather than silently losing a response. [Official app-server reference](https://learn.chatgpt.com/docs/app-server).

Keep the client inside the existing ephemeral Linux worker: no host bind mount, no worker network, read-only root, protected authentication files, denied model-child writes/network/broker access, per-account binding and current allowance checks. SIGINT/SIGTERM handlers close the client and run task-specific container/volume teardown. Authentication codes are displayed transiently and are never written to a file.

Two actual visual Medium turns and one same-video Low comparison completed with validated transcript/frame references after the fixes. A separate production app export, actual local runner invocation and production result import completed using prepared text only. These are distinct tests: the app comparison does not supply visual frames or process the saved-link backlog. Native full-cloud media preparation still requires verified current enforced network policy. Full V1, knowledge evaluation and continuous issue-to-PR acceptance remain separate requirements. Exact timings, failures, quality limitations and release results are in [implementation status](../implementation-status.md).

Affected checks: broker delayed-response/half-duplex/idle/absolute-cap tests; official-client exit and protocol-size tests; provider schema identity/coverage constraints; existing tenancy, correction, evidence, expiry and budget tests; authenticated child probes; real subscription inference and production comparison readback. The [operator runbook](../operations/subscription-analysis-trials.md) retains the supported execution procedure.
