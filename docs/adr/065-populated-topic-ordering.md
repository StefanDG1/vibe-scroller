# Show useful topics before empty history

Mode: reference. Decision October 6, 2026. Status: implementation candidate.

After the corrected personal run saved 103 genuine posts, production's default first page still showed older empty topics before the newly populated knowledge. Creation order made useful combined knowledge harder to discover. Empty history and owner corrections must remain accessible.

Order the default workspace topic query by owner pin first and included insight count second, descending, using a workspace-prefixed index before pagination. Keep existing search, source filters, page bounds, membership checks and the original index. Legacy topics with an absent count remain readable. Counts describe available knowledge, not truth, quality or benefit. No topic is renamed, merged, excluded or deleted by this ordering change.

Acceptance covers a first page containing pinned and populated topics despite more than thirty older empty records, complete subsequent pagination including legacy records, and refusal of foreign workspace access. Production mobile and desktop checks must verify useful first-page discovery after the index deployment. This change does not authorize inference, issue publication or additional spending.
