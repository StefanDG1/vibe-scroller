# Keep evolving knowledge private to a workspace and publish reviewed issues

Mode: reference. Decision October 3, 2026. Status: owner-approved product direction; implementation planned. [The V1 plan](../V1-KNOWLEDGE-LIBRARY-PLAN.md) defines dependencies and acceptance.

The owner wants GitHub's All repositories grant with an app checklist for the active subset, reuse of saved-post insights across selected projects, automatic connections and combined knowledge, clear library screens, and detailed GitHub issues. The owner confirmed separate workspace libraries and automatic organization. AI proposes business context by default; the user can confirm it in one action or correct it.

The current app already has repository grants, single-repository selection, quoted AI profile drafting, categories and source-specific matching/plans. Extend those paths. Do not rebuild them as parallel products. Keep the existing database/provider stack and preserve old single-source records. Proposed multi-source references, topic versions and organization feedback make automatic updates auditable. Manual corrections take priority. No customer-content training or cross-workspace cache is authorized.

A GitHub installation grant and an app selection are separate. Unselected repositories contribute no code to context. Selecting a project, accepting a profile or approving organization does not approve execution or issue publication. Organization uses explicitly bounded existing funding and stops at its limits. AI guesses remain unconfirmed until reviewed; code cannot establish every business fact.

Issues become an alternative reviewed output to coding. Publication requires verified issue permissions, current access and separate approval of exact target/title/body. Repository visibility and departing private information are explicit. Unknown results reconcile before retry. Existing separate coding, patch, draft-PR and merge boundaries remain. A closed issue is not measured benefit.

This is V1 scope. V2, new businesses, account provisioning, advertising and autonomous customer deployment remain excluded. The planning request changes no runtime provider permission, budget, pricing, database schema or production behavior. Required evidence covers isolation/deletion, bounded updates, persistent corrections, current repository context, real issue integration, mobile/desktop use and independent comprehension. The plan retains uncompleted earlier release/study gates.
