# Keep Home metadata atomic and bounded

Mode: reference. Decision October 7, 2026. Status: deployed and operator-enabled October 7 after bounded authenticated engineering acceptance. External usability and cost acceptance remain open.

The migration checkpoint defaults compact Home off. An explicit authenticated `homeMode=compact` URL selects the same bounded authorized query for acceptance; it cannot grant access or relax evidence/cost limits. After exact CI, the compatible frontend can deploy with ordinary Home unchanged. The operator enables compact Home only after real captures, using an internal mutation that requires a complete migration and unlocked recovery. This avoids copying production authentication into staging or altering login callbacks merely to test the interface. Disabling the checkpoint retains the compatible full path for rollback.

A same-millisecond manual correction could previously retain its old timestamp revision. The regression reproduced a stale recommendation, including through the existing full-content reader. Manual source corrections and category assignments now advance the revision to at least the prior timestamp plus one millisecond. They preserve the reference format and do not relink old conclusions to corrected evidence. Legacy proposals without versioned references remain in the ordinary review list rather than being recommended as current evidence on Home.

Home needs titles, current processing states and useful next actions. It does not need transcripts, repository content, proposal bodies or hidden operational lists. Preserve canonical records and IDs. A compact `dashboardCards` table contains an explicit field allowlist for sources, repositories, proposals and runs. Existing `convex-helpers` mutation triggers update these cards in the same transaction as canonical writes. Projection failures abort the write. This adds reads and writes to affected mutations; it does not establish measured cost savings.

Every Home query checks the active account, membership and actual private owner. It reads at most 31 cards for each of four kinds and returns at most 30 of each. Proposal eligibility checks exact source generation, revision, insight identity and rights, plus confirmed current repository SHA/profile. Additional card lookups and reference checks each have a shared limit of 128. Missing or over-budget evidence hides the proposal. Full approval and evidence checks remain authoritative when an idea is opened. Thirty current notification identities/read flags preserve existing browser updates without loading message bodies on Home. Recent-page coverage is not a full-library count.

The internal backfill processes ten canonical records per transaction, checkpoints a cursor and schedules its next page. It neither rewrites source versions nor queues inference. Atomic triggers handle concurrent writes. Until the checkpoint completes, server loaders retain the compatible existing full path. Restore operations keep private reads locked and must rebuild/verify compatible projections before reopening; a passing lock test is not a serving restore rehearsal. Do not import or alter canonical records through an unwrapped application writer.

The application keeps compact Home state separate from full editor state. Opening capture or an idea loads actual authorized content/options. Switching views fences earlier responses and preserves serialized polling. Authorization failures discard both caches. Explicit shared capture drafts initially load full context. Existing editors, provider restrictions, reservations, unknown-cost holds and publication/coding approvals remain unchanged.

Tests: `tests/dashboard-projection.test.ts` covers bounded interrupted backfill, private payload exclusion, source revision invalidation, deletion and authorization/recovery locks. `apps/starter/product-errors.test.ts` covers HTTP 403 on lost workspace/account access so clients can clear private caches. These are local fixture tests, not real-account, serving recovery or provider acceptance.
