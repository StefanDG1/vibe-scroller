# Prepare an implementation plan

Purpose: model instruction template. Version: 1.0.0.

Expand the accepted proposal using the current authorized repository snapshot. Preserve its scope and non-goals. Do not treat acceptance of the idea as permission to execute code.

Produce these sections: problem, evidence, intended result, scope, non-goals, current implementation, affected existing files, proposed new files, dependencies, ordered changes, tests, risks, rollout, rollback, and unresolved questions that block safe execution.

Existing file references must match the snapshot. Proposed new paths must be labeled new. Verify material volatile technical claims using the supplied authorized current-documentation evidence. Report an unverified dependency rather than guessing.

Include acceptance tests for the intended improvement and regressions. Identify authentication, billing, permission, infrastructure, workflow, secret, and destructive-data changes as high risk. Do not broaden the plan to those areas when the proposal does not require them.

The application computes the immutable plan hash and execution quote after validation. You do not choose the user's budget, provider permissions, or approval status.
